# Slack 完全再現仕様書 — 03. メッセージ機能詳細

## 3.1 メッセージコンポーザ（入力欄）

### 構成要素
- リッチテキストエディタ（WYSIWYG）。内部表現は **Block Kit の `rich_text` ブロック**。
- ツールバー: 太字/斜体/打消し/コード/リンク/順序付きリスト/箇条書き/引用/コードブロック。
- 左: ＋（ショートカット/ファイル/アプリ）。右: 絵文字、メンション(@)、ビデオ/音声クリップ、スレッド送信ボタン、送信。
- 入力モード切替: リッチテキスト ⇄ Markdown 入力（設定で選択）。

### 入力中の挙動
- `@` → ユーザー/usergroup/`@here`/`@channel` のオートコンプリート（あいまい一致、表示名/本名/handle 横断）。
- `#` → チャンネルオートコンプリート。
- `:` → 絵文字オートコンプリート（最近使用＋頻度順）。
- `/` を行頭 → スラッシュコマンドのオートコンプリート（説明・引数ヒント付き）。
- `↑`（空欄時）→ **直前の自分のメッセージを編集**モードに。
- 下書きは**サーバ同期される drafts**（多端末で同期、`drafts.*`）。
- Shift+Enter = 改行、Enter = 送信（設定で逆転可）。

## 3.2 mrkdwn（Slack Markdown 方言）— 厳密仕様

Slack の `text` は標準 Markdown ではない。**正確に再現すべき差分**:

| 記法 | 入力 | 結果 |
|---|---|---|
| 太字 | `*bold*` | **bold**（`**` ではない！） |
| 斜体 | `_italic_` | *italic* |
| 取り消し線 | `~strike~` | ~~strike~~ |
| インラインコード | `` `code` `` | `code` |
| コードブロック | ` ```...``` ` | 整形済みブロック（言語指定は無視/装飾のみ） |
| 引用 | 行頭 `>` | ブロック引用。`>>>` で複数行 |
| 箇条書き | `•`（実体は rich_text list） | リスト |
| リンク | `<https://url|表示文字>` | ハイパーリンク |
| 自動リンク | URL 直書き | 自動リンク化＋unfurl |

### エンティティのエンコード（保存形式）
表示テキスト内の特殊参照は `<...>` でエンコードされて保存される:
- ユーザー: `<@U023BECGF>`（表示時に名前解決）
- ユーザー名指定: `<@U023BECGF|displayname>`
- チャンネルリンク: `<#C024BE91L|channel-name>`
- usergroup: `<!subteam^S0614TZR7|@engineering>`
- 特殊メンション: `<!here>`, `<!channel>`, `<!everyone>`
- 日付フォーマット: `<!date^1392734382^{date_short} at {time}|fallback>`（受信側 TZ でローカライズ表示）
- リンク: `<http://example.com|label>`
- エスケープ必須文字: `&`→`&amp;`, `<`→`&lt;`, `>`→`&gt;`

> **再現の肝**: 保存は「mrkdwn 原文 + エンコード済みエンティティ」。表示時にユーザー/チャンネル/日付を解決して描画する。検索・通知判定もこのエンコード上で行う。

## 3.3 Block Kit（リッチ構造表現）

メッセージのリッチ表現の正本は `blocks`（配列）。詳細は `09-platform-apps.md`。ここでは表示要点:
- `rich_text`（ユーザー投稿の正体）, `section`, `divider`, `image`, `actions`, `context`, `header`, `input`, `file`, `video`, `call`。
- クライアントは blocks があれば blocks を、無ければ `text`(mrkdwn) を描画。`text` は常に通知/検索/フォールバック用に保持。

---

## 3.4 メンションと通知トリガ
- `@user` → 当人に mention 通知（DND/設定に従う）。
- `@here` → そのチャンネルの**現在 active** なメンバーに通知。
- `@channel` → メンバー全員（オフライン含む）に通知。
- `@everyone` → #general 全員。
- usergroup `@team-name` → メンバー全員に通知（展開）。
- mention 権限制限（`@channel`/`@here` を誰が使えるか）を team_pref で制御可能。

---

## 3.5 編集

- 自分のメッセージのみ（管理者は他者編集を許可しない＝削除のみ可設定）。
- 編集可能ウィンドウ: `msg_edit_window_mins`（既定 無制限、管理者が分単位で制限可、0=不可）。
- 編集後、メッセージに `(edited)` ラベル。`edited={user,ts}`。
- RTM `message_changed` を全クライアントへ。`previous_message` 同梱。
- 編集はメンションを増減し得る → 新規 mention には通知し直す挙動（実装依存だが Slack は再通知を抑制的に扱う）。
- eDiscovery 対象では編集履歴を完全保持（`message_history`）。

---

## 3.6 削除

- 自分のメッセージ削除可（編集と独立に許可制御 `allow_message_deletion`）。
- 管理者は他者メッセージ削除可（権限による）。
- 親メッセージ削除時の子スレッド: スレッド返信は残り、親は tombstone 表示（「削除されました」）にできる。
- RTM `message_deleted`。論理削除（コンプラ保持あり）。
- ファイル削除は別途 `files.delete`。共有先すべてから消える。

---

## 3.7 リアクション

- 任意の絵文字（標準/カスタム/スキントーン）でリアクション。
- 同一絵文字は集約カウント。ホバーで誰が押したか（最大表示数あり）。
- 自分が押した絵文字はハイライト、クリックでトグル。
- ショートカット: メッセージホバー → 絵文字ピッカー。よく使う絵文字をクイック表示。
- RTM `reaction_added/removed`。
- リアクションは通知対象になり得る（設定: 自分の投稿へのリアクション通知）。

---

## 3.8 メッセージアクション（ホバーメニュー / オーバーフロー）

ホバー時の右上アクション（完全再現リスト）:
- 絵文字リアクション追加
- スレッドで返信 / スレッドを開く
- 共有（他チャンネル/DM へ転送、コメント添付可）
- 保存（Save for later / 旧 Star）
- リマインダー設定（「30分後に通知」等）
- ピン留め（to channel）
- コピー（テキスト / リンク=permalink）
- 編集 / 削除（権限時）
- メッセージのマーク（ここから未読に）
- アプリ提供のメッセージショートカット（例: Jira 起票、To-do 化）

---

## 3.9 共有（Share message）

- 既存メッセージを別チャンネル/DM に転送。元メッセージは**引用カード**（attachment 形式）として埋め込まれ、permalink を保持。
- 追加コメントを添えられる。
- private チャンネルのメッセージを public に共有する際は警告。

---

## 3.10 ピン留め

- チャンネルごとに重要メッセージ/ファイルを固定。
- 上部の「ピン留めアイテム」一覧からアクセス。
- 誰でも（または権限設定により）ピン可。上限あり（実機 ~100）。

---

## 3.11 保存（Saved / Later）

- 旧称 Star。現在は「後で見る (Later)」とブックマーク統合。
- 状態: 進行中 / アーカイブ / 完了。リマインド時刻を付けられる。
- 左サイドバー上部「Later」から横断アクセス。

---

## 3.12 リマインダー

- `/remind me to <text> at <time>` / `/remind #channel ...` / `/remind @user ...`。
- 自然言語時刻パース（「tomorrow at 9am」「every weekday」「in 30 minutes」）。
- 指定時刻に Slackbot DM で通知。完了/スヌーズ可。

---

## 3.13 スニペット / コード / Post

- **コードスニペット**: ＋メニューから言語指定でコードを投稿。シンタックスハイライト、行折返し、ファイル化（`mode=snippet`）。
- **テキストスニペット**: 長文をファイル化して折りたたみ表示。
- 旧 **Post**（リッチ文書）は現在 **Canvas** に統合（07 参照）。

---

## 3.14 unfurl（リンク展開）

- URL を投稿すると、サーバが OGP/oEmbed を取得し**プレビューカード（attachment）**を後付けで添付。
- アプリは特定ドメインの unfurl を `links.shared` イベント＋`chat.unfurl` で**カスタム展開**できる（例: Jira/GitHub リンクが情報カードになる）。
- 画像/動画 URL はインライン表示。ユーザーは unfurl 削除可。
- 1メッセージ内の unfurl 数に上限。

---

## 3.15 スケジュール投稿

- `chat.scheduleMessage` 相当。コンポーザの送信ボタン横メニューから日時指定。
- 予約一覧から編集/取消可（送信前まで）。
- 相手の TZ を考慮した推奨時刻サジェスト。

---

## 3.16 メッセージの種類（subtype 別表示）

| subtype | 表示 |
|---|---|
| (none) | 通常メッセージ |
| `bot_message` | bot 投稿（カスタム名/アイコン可） |
| `me_message` | `/me` アクション（斜体の三人称風） |
| `channel_join`/`leave` | 「X さんが参加しました」（折りたたみ集約表示） |
| `channel_topic`/`purpose`/`name` | システム通知行 |
| `channel_archive`/`unarchive` | システム通知 |
| `thread_broadcast` | スレッド返信のチャンネル本流表示 |
| `file_share` | ファイル添付メッセージ |
| `reminder_add` | リマインダー設定通知 |
| `tombstone` | 削除済み表示 |

- join/leave 等のシステムメッセージは連続すると**集約折りたたみ**（「3人が参加しました」）。
