# 実装仕様 M11 — モバイルクライアント（iOS/Android）固有仕様・デスクトップとの差分

## 1. アーキテクチャ方針
- ネイティブ実装（iOS: Swift/SwiftUI+UIKit、Android: Kotlin/Compose）。WebView 主体にしない。
- 同期層はデスクトップと同一契約（M3 の boot / WS / gap-fill / outbox）を共有。
- ローカル永続: SQLite。テーブルは messages/channels/users/drafts/outbox/emoji の
  サブセット + LRU 上限（メッセージは会話毎直近 500 件 + ピン/保存分）。

## 2. アプリライフサイクルと接続戦略（デスクトップとの最大の差）

```
[FOREGROUND] WS 常時接続（M3 と同一）
     │ バックグラウンド遷移
     ▼
[BACKGROUND_GRACE] iOS: ~30s / Android: 数分（OS 裁量）
     WS を維持し既読同期等を完了 → OS の期限で切断
     ▼
[SUSPENDED] WS なし。すべての更新はプッシュ経由
     │ 復帰 (foreground)
     ▼
[RESUME] 1. キャッシュから即時描画（スピナーを出さない）
         2. client.counts で差分判定（M3§6 gap-fill と同一手順）
         3. WS 再接続。表示中チャンネルを優先穴埋め
目標: 復帰から表示可能まで < 500ms、最新化まで < 3s
```

- **プッシュが同期の代替経路になる**: SUSPENDED 中の新着はプッシュ通知のペイロード
  （M5§4）でローカル DB に挿入し、バッジを OS API で直接更新する。
- サイレントプッシュ（content-available / data message）で「既読化・通知取り消し・
  プロフィール変更」を裏で適用（他端末で読んだ通知をシェードから消す）。

## 3. プッシュ通知の実装規定

| 項目 | iOS | Android |
|---|---|---|
| 経路 | APNs (token) | FCM |
| 表示 | Notification Service Extension で復号・整形 | data message を受けアプリが Notification 生成 |
| グルーピング | thread-id = channel_id | groupKey = channel_id + チャンネル別 NotificationChannel |
| アクション | 返信(インライン)/既読/絵文字 | RemoteInput 返信/既読/絵文字 |
| 取り消し | サイレントプッシュで該当 id を removeDelivered | 同様に cancel |
| 通知チャンネル(Android) | – | 「メンション」「DM」「Huddle」「その他」を NotificationChannel として分離（OS 設定で粒度制御可能に） |
- インライン返信は outbox 経由（M3§7。オフラインなら蓄積して後送）。
- プッシュ重複: event 由来とポーリング由来は dedup key = channel+ts。

## 4. ナビゲーション構造

```
下部タブ: [Home] [DMs] [Activity] [Search] [You]
Home    : ワークスペース切替(上部) + サイドバー相当のリスト（セクション/未読フィルタ）
チャンネル画面: スタック push。スワイプバックで戻る
スレッド : チャンネル上にさらに push（右ペインは存在しない）
You     : ステータス設定 / DND / プロフィール / 設定
```
- デスクトップの「右ペイン」概念は無く、**全て push 遷移**で表現する。
- ワークスペース切替: Home 上部のアイコン長押しでスイッチャーシート。

## 5. 入力・操作の差分

| 操作 | モバイル規定 |
|---|---|
| メッセージ長押し | アクションシート（リアクション最頻5 + 全アクション。M3 のホバーバー相当） |
| スワイプ（メッセージ右→左 or 左→右） | スレッド返信（設定で「未読にする」へ変更可） |
| Enter キー | **常に改行**。送信は送信ボタンのみ（デスクトップと逆） |
| 下書き | 入力途中で離脱→ drafts に自動保存・全端末同期 |
| 添付 | フォトピッカー/カメラ/ファイル。複数選択 ≤10。アップロードは M4§10 と同一の3段 |
| 共有シート | OS share extension から任意アプリのコンテンツを チャンネル選択→コメント付きで投稿 |
| プルリフレッシュ | チャンネルリスト/会話で手動 gap-fill |
| 画像ビューア | ピンチズーム、スワイプで次/前、保存・共有 |

## 6. オフライン規定
- 閲覧: キャッシュ済みチャンネルは機内モードで全面閲覧可（「最終更新 n分前」バナー）。
- 送信: outbox に積み、接続回復で FIFO 送信（チャンネル毎直列、client_msg_id 冪等）。
  失敗表示・再試行はデスクトップ M3§7 と同一。
- 既読: ローカルで last_read を進め、回復時に conversations.mark を後送
  （サーバ側は max(クライアント値, 現在値) を採用し巻き戻さない。
   ※明示的な Mark unread 操作のみ巻き戻しフラグ付きで送る）。

## 7. モバイル固有の機能
- **生体認証ロック**: FaceID/指紋でアプリロック（組織ポリシーで強制可）。
- **EMM/MDM**: AppConfig 経由でコピー禁止/スクショ禁止(Android FLAG_SECURE)/
  ダウンロード禁止/許可ワークスペース固定。
- **ウィジェット/ショートカット**: 未読サマリ、特定チャンネルへのジャンプ、
  Siri/App Shortcuts・Android App Shortcuts（DM 上位3件）。
- **Huddle**: バックグラウンドで音声継続（CallKit / foreground service + 通話通知）。
  CarPlay/Android Auto は通知読み上げのみ。
- **カメラからのドキュメントスキャン**、音声 Clip の録音はネイティブ UI。

## 8. パフォーマンス目標（計測基準）
| 指標 | 目標 |
|---|---|
| コールドスタート→Home 表示 | < 2.0s (P50) / < 4s (P90) |
| 通知タップ→該当メッセージ表示 | < 1.5s |
| 復帰→キャッシュ描画 | < 500ms |
| スクロール | 60fps、画像はプレースホルダ→プログレッシブ |
| バッテリー | バックグラウンド消費はプッシュ駆動のみ（常時ポーリング禁止） |

## 9. 受け入れ基準
```gherkin
Scenario: 機内モードでの送信
  Given 機内モードで DM に 3 件送信した
  When  通信が回復する
  Then  3 件が入力順で送信され、重複せず、他端末にも 1 回ずつ表示される

Scenario: 別端末既読の通知消去
  Given 携帯に未読メンションの通知が表示されている
  When  デスクトップでそのチャンネルを既読にする
  Then  携帯の通知シェードから該当通知が自動で消え、バッジ数が減る

Scenario: 通知タップの深リンク
  Given スレッド返信の通知をタップした
  Then  チャンネル→スレッドの順にスタックが構成され、戻る操作でチャンネルに戻れる
```
