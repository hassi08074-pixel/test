# Slack 完全再現仕様書 — 04. チャンネル / DM / MPIM / スレッド / 既読

## 4.1 チャンネルの種類

| 種類 | ID | 特徴 |
|---|---|---|
| Public channel | `C` | チーム全員が検索・参加可能。デフォルト公開 |
| Private channel | `C`(is_private) | 招待制。検索不可。メンバーのみ |
| DM (IM) | `D` | 1:1。常設 |
| Group DM (MPIM) | `G` | 2〜9人の多人数 DM。トピック/目的なし |
| Shared channel | `is_shared` | Slack Connect / Grid 共有 |
| #general | `is_general` | 既定の全員参加チャンネル。削除不可・名前変更可・退出不可（設定依存） |

### 命名規則
- 小文字英数・ハイフン・アンダースコア、最大 80 文字、チーム内一意（正規化名で衝突判定）。
- 空白/大文字は不可（自動変換）。先頭の `#` は表示装飾。
- 推奨プレフィックス慣習（任意）: `proj-`, `team-`, `help-`, `social-`。

---

## 4.2 チャンネルのライフサイクル・操作

- **作成**: 名前・public/private・説明・初期メンバー。権限 `who_can_create_channels`。
- **トピック / 目的 (Purpose)**: 短い説明。ヘッダに表示。`channel_topic`/`channel_purpose` システムメッセージ。
- **招待 / 退出 / 削除（キック）**: `conversations.invite/kick/leave`。
- **アーカイブ**: 読み取り専用化（履歴は残る）。再オープン可。`who_can_archive_channels`。
- **削除**: 管理者のみ。履歴ごと削除（コンプラ保持を除く）。
- **public⇄private 変換**: public→private は可（一方向が原則。private→public は制限/不可）。
- **名前変更**: `channel_name` システムメッセージ、ID 不変。
- **ブックマーク / ピン留めリンク**: チャンネルヘッダにリンク/ファイルをピン。
- **チャンネル管理**: メンバー一覧、通知設定、ワークフロー、インテグレーション、Canvas タブ。

---

## 4.3 チャンネル参加モデル
- public は誰でも `conversations.join` で参加（履歴を遡って閲覧可能）。
- private は招待が必要。招待者は既存メンバー。
- 参加時に**過去ログ全体が閲覧可能**（メール的「参加前は見えない」ではない。これが Slack 哲学）。
  - private で「参加前の履歴を見せない」設定も可（Enterprise）。
- single-channel guest は1チャンネルのみ。

---

## 4.4 DM / MPIM

- DM は相手を選ぶと自動生成（既存があれば再利用）。`is_im`。
- 自分自身への DM（メモ用）も可。
- MPIM は参加者集合で一意。2〜9人。メンバー増減で別 MPIM に。
- DM/MPIM はサイドバーの「ダイレクトメッセージ」セクション。
- DM には**既読インジケータ**（相手がどこまで読んだか）を表示し得る（チャンネルには無い）。
- DM の通知は既定「すべてのメッセージ」。

---

## 4.5 スレッド（詳細挙動）

### モデル
- 親メッセージのアクション「スレッドで返信」→ 右ペインにスレッドビュー。
- 返信は `thread_ts=親ts`。親には `reply_count`, `reply_users`（アバター列）, `latest_reply` を表示。
- **「Also send to channel」**チェック → `thread_broadcast`。返信がチャンネル本流にも出る。

### スレッドの既読・購読
- スレッドに返信 or 明示フォローすると**購読 (subscribed)** 状態に。
- 購読スレッドへの新着は「スレッド」ビュー（左サイドバー上部「Threads」）に集約表示＆通知。
- `thread_marked` でスレッド既読を多端末同期。
- スレッド内 `@mention` は通常通り通知。

### 「Threads」ビュー
- 自分が参加/購読する全スレッドの新着を一覧。チャンネル横断。
- 各スレッドを展開してその場で返信可能。

---

## 4.6 既読・未読モデル（再掲＋詳細）

- 既読状態 = `channel_members.last_read`（最後に読んだメッセージ ts）。
- チャンネルを開く → 表示完了で last_read を最新に更新（`conversations.mark`）。
- **「New messages」境界線**: 開いた時点の last_read 位置に区切り線「New」を描画。スクロールで既読化。
- **「ここから未読にする (Mark unread)」**: 任意メッセージから未読扱いに戻す（last_read を巻き戻す）。
- ミュートチャンネル: 未読でも太字化しない。mention は別途バッジ可。
- 全既読: 「すべて既読にする」操作。

---

## 4.7 サイドバー編成

- セクション: Starred / Channels / Direct Messages / Apps（既定）＋**カスタムセクション**（ユーザー定義、ドラッグ整理、絵文字付き）。
- 表示フィルタ: 全て / 未読のみ / メンション。
- 並び替え: アルファベット / 最新アクティビティ / 未読優先。
- ミュート済み・既読は折りたたみ可能。
- 各行: 未読=太字、mention=赤バッジ、外部共有=ダイヤ印、private=鍵、connect=◇。

---

## 4.8 チャンネル横断機能
- **チャンネルブラウザ**: 全 public チャンネルを検索・プレビュー・参加。メンバー数/アクティビティ表示。
- **おすすめチャンネル**: アクティビティに基づく推薦。
- **デフォルトチャンネル**: 新規メンバーを自動参加させるチャンネル集合（team_pref）。

---

## 4.9 Slack Connect（組織間共有）

- **共有チャンネル**: 異なる組織の Slack 同士で1チャンネルを共有。各組織のメンバーが同じチャンネルで会話。
- 招待フロー: メール/リンクで相手組織管理者の承認 → 接続確立。
- 各組織はそれぞれの管理ポリシー（DLP/保持）を自組織のメッセージに適用。
- 外部メンバーは視覚的に区別（組織名バッジ、外部マーク）。
- **Connect DM**: 別組織の個人と DM。
- 管理者は外部共有の許可/制限、承認制を設定可能。
