# Slack 完全再現仕様書 — 08. ファイル / アップロード / プレビュー

## 8.1 アップロードフロー（現行2段階方式）

Slack の現行アップロードは**3ステップ**（旧 `files.upload` は非推奨）:

1. **`files.getUploadURLExternal`** — `{filename, length}` を渡し、署名付きアップロード URL と `file_id` を取得。
2. **POST（バイナリ）** — その URL に実体を直接 PUT/POST（オブジェクトストア / CDN へ直行。API サーバを経由しない）。
3. **`files.completeUploadExternal`** — `file_id` 配列＋共有先 `channel_id`/`thread_ts`/初期コメントを渡して確定。確定時に `file_share` メッセージが投稿される。

> 再現の肝: **アップロード本体を API から切り離し、署名付き URL でストレージへ直接転送**。これでスループットとスケールを確保。

## 8.2 ファイル種別と処理
- 画像（png/jpg/gif/webp/heic）: 複数解像度サムネ事前生成（64〜1024px）。EXIF 回転補正。インライン表示。
- 動画（mp4/mov）: トランスコード、サムネ、インラインプレイヤー、スクラブ。
- 音声: 波形＋プレイヤー。Clip は文字起こし。
- PDF/Office/テキスト: プレビューレンダリング（ページサムネ）。
- コード/スニペット: シンタックスハイライト、行番号。
- 外部ファイル（`is_external`）: Google Drive/Dropbox/Box 等の参照のみ（実体は外部、権限も外部）。

---

## 8.3 共有・権限
- ファイルは複数チャンネル/DM に共有可能（`shares` に記録）。1実体を多所共有。
- アクセス: そのファイルが共有された会話の閲覧権を持つ人のみ。
- `url_private` は要認証ダウンロード（署名付き、時限）。
- **パブリックリンク**: ユーザーが明示トグルすると `permalink_public` 発行（誰でも閲覧）。管理者が無効化可。
- ファイルコメント（旧）→ 現在はファイル共有メッセージへのスレッド。

---

## 8.4 ファイルブラウザ・管理
- チャンネルの「ファイル」タブ。種別/投稿者/日付でフィルタ。
- ワークスペース全体のファイル検索（`has:pdf` 等）。
- 削除（`files.delete`）は全共有先から消える。所有者/管理者。
- ストレージ容量はプラン依存（Free は上限、有料は拡大）。古いファイルの自動削除（保持ポリシー）。

---

## 8.5 セキュリティ/コンプラ
- DLP スキャン（機密検出）対象。
- マルウェアスキャン。
- 保持ポリシー（retention）でファイルも自動削除対象。
- eDiscovery エクスポート対象。
- ダウンロード制御（モバイル/未管理端末でのダウンロード禁止: EMM/MDM 連携）。
